# ForecastIQ — Infrastructure as Code (Phase 1)

**Version**: 1.0
**Status**: Approved — Phase 1 Architecture
**Authority**: `docs/architecture/06-deployment-architecture.md` §9; constraints (Terraform only where it provides repeatability without excessive overhead)

---

## 1. IaC Scope Decision

Hybrid model matched to the platform mix:

| Resource | Management | Rationale |
|----------|-----------|-----------|
| Cloudflare DNS records (api, app) | **Terraform** (cloudflare provider) | API-manageable, state fits, fast failover changes |
| Neon project + database + roles (if Neon selected) | **Terraform** (neon provider) | Reproducible DB provisioning incl. credential rotation flow |
| VPS server | **Scripted bootstrap** (cloud-init + `deploy/bootstrap.sh`) | One machine; Terraform hetzner provider adds fragile API dependency for one resource; script is simpler and testable |
| Volume attach/format/mount | Bootstrap script | Same |
| Caddy config | **Committed Caddyfile** (deployed by pipeline) | Config-as-code without provider lock |
| systemd units | Committed unit files (pipeline installs) | Same |
| grafana-agent config | Committed YAML (pipeline deploys; secrets via env) | Same |
| Grafana dashboards/alerts | **Committed JSON/YAML** synced by pipeline (Grafana HTTP API) | Dashboards-as-code, versioned |
| Cloudflare Pages project | Manual bootstrap once (UI wizard) + documented | Adequate for one static site; Terraform support limited |
| Supabase project + auth config | Manual bootstrap once + **runbook documenting every setting** | Vendor CLI/Terraform maturity low; settings stable |
| B2 bucket | Manual once + runbook | One bucket |

**Rule:** anything bootstrapped manually is documented step-by-step in `deploy/BOOTSTRAP.md` with verification commands — reproducibility without tooling overhead.

## 2. Terraform Layout

```text
terraform/
├── main.tf                  # providers, backend
├── cloudflare.tf            # zone records: api A → VPS IP, app CNAME → Pages
├── neon.tf                  # project, database, roles (app + migrate), branch (dev optional)
├── variables.tf             # minimal vars (no defaults for secrets)
├── outputs.tf               # connection strings (sensitive), DNS names
└── terraform.tfvars.example # committed template (no values)
```

| Aspect | Specification |
|--------|---------------|
| State storage | Cloudflare R2 or Terraform Cloud free tier (remote state, encrypted, locked) |
| State encryption | Backend-side (SSE) |
| Environment separation | Single production workspace (MVP); state key includes `prod`; new environment = new key prefix |
| Secrets exclusion | **Never in tf files or state inputs**: DB passwords generated by provider (Neon creates them; output marked sensitive, exported once to secret store); API tokens via TF_VAR_ env (CI secrets) |
| Provider pinning | Exact versions locked in `.terraform.lock.hcl` |
| Modules | None at MVP (flat files; module extraction when resource count justifies) |
| Naming | `forecastiq-<resource>` prefix; labels: `project=forecastiq`, `managed-by=terraform` |
| Cost controls | Neon storage alerts (vendor); no autoscaling resources exist; `terraform plan` review before apply (always human) |
| Apply policy | Plan committed to PR for review; apply via CI with manual approval (same gate as deploy) |

## 3. Bootstrap Script Contract (`deploy/bootstrap.sh`)

Idempotent (safe to re-run):

```text
1. System packages (caddy, postgresql-client, grafana-agent, rclone, fail2ban)
2. App user (forecastiq, no login shell)
3. Volume: detect, format if empty (ext4, LUKS optional flag), mount /var/lib/forecastiq
4. Directories + permissions (releases/, current symlink, payloads/, backups/)
5. systemd units installed + enabled (not started)
6. Caddyfile installed; caddy validate
7. Firewall (ufw: 22, 80, 443 only; metrics port localhost-only)
8. fail2ban ssh profile
9. Cron entries (backup.sh nightly, restore-test monthly)
10. Verification section: prints checklist (mount ok, units present, ports)
```

## 4. Drift Management

| Resource class | Drift detection |
|----------------|-----------------|
| Terraform-managed | `terraform plan` in weekly CI schedule → issue on non-empty plan |
| Committed configs (Caddyfile, units, grafana) | Pipeline deploys on every main merge (self-healing: config always converges to repo) |
| Manual resources | Quarterly ops checklist review against BOOTSTRAP.md |

## 5. Disaster Recovery Integration

VPS rebuild = new server + `bootstrap.sh` + pipeline deploy + DNS update (Terraform variable change for IP). All steps in runbooks; IaC pieces tested by the quarterly rollback/rebuild drill.
